### 点数 / 花色图案链路（2026-10-21，仅调查，尚未实现替换）

- **数据与绘制**：`GetCardById().Number -> NormalCard.CardInfo -> cardNumberOri/cardNumber`；读当前点数用 `Card.CardNumber`，不能用配置值替代，修改 setter 会经 `CARD_CHANGE -> onCardChange -> UpdateCardFace` 重画。普通 `iVi.UpdateCardFace` 在父类底图之后，将 `GetFlowerResName/GetNumberResName` 纹理赋给独立 `bmpFlower/bmpNumber`。显示花色为 `DisplayFlower`（即 `IsModyfifyByServer ? - **技能旁路**：`ChangeCardFlowerNumber -> stackCardContainer.cardUiDict -> ChangeFlowerAndNumber(flower,number)` 直接改显示、不写牌模型，已有黑桃5/红桃5调用。自定义图案若仅在普通刷新后重读模型，会漏掉此分支；旁路应按入参映射，并让后续原生刷新恢复模型展示。装备 `sVi.UpdateCardFace` 有独立实现及 `other_` 资源；扑克牌 `poker_` 另有编码，不能只挂普通父类就宣称全界面覆盖。
- **现状与后续边界**：现有 `initCardThemeFeature -> installCardThemeRuntime -> window.__cardTheme` 管底图纹理和 UI 注册；没有本次新图案开关或资源加载器。已拆 `cards.atlas` 111项不含30个普通符号键，仅改 `cards.png` 不会换点数/花色。后续可在真实加载链接独立符号主题，拥有自己的纹理/启用/异步代次，原生 `UpdateCardFace/ChangeFlowerAndNumber` 后只换图元纹理，缺失回退；复用注册接口，保留底图/卡背/标签挂钩，不改游戏点数模型。
- **生命周期与回归**：普通 `layout` 将点数/花色设为19×17或16×14，改变显示尺寸还需协调布局。保留无牌/空牌/虚拟牌、`dontUpdateCard`、`HideFlowerAndNumber`/配置窗口隐藏；`Clear`/复用/换局清掉自有显示状态，关闭后按当前数据重画，异步防旧UI/Card污染，卸载不得覆盖后装包装器。本次只调查和文档，无运行代码回退；63项抽取方法检查通过，未验证自定义素材加载或游戏内替换。详情、来源哈希和临时验证文件见 [OL指南](卡牌说明.md) 同名章节，手工索引 `manualLookupNotes.cardRankSuit`。
