# 单卡检查点与守护恢复

本地 `controller.py` 由主会话在单卡的关键节点调用，原子保存 `runtime/state.json` 和 `heartbeat.json`。独立 `watchdog.py` 每15秒检查一次，默认15分钟（900秒）无心跳才告警；它不调用生成接口、不重启 Codex、不接管正在生成的卡，不修改图片、清单或完成记录。应用关闭后无法自行取得内置图像工具权限，恢复生成仍需有效会话。

## 状态与职责

- `runtime/state.json`：主流程唯一可写检查点，包含当前卡、阶段、预期产物路径、已落盘产物哈希、完成卡和失败原因。`done` 已提交记录不可覆盖；重复提交完全相同的文件是幂等操作。
- `runtime/heartbeat.json`：控制器心跳镜像。守护以 state 内同次原子提交的心跳为准，避免两文件写入时序误判。
- `runtime/watchdog.pid`：带 PID/随机标识的独占锁，阻止重复启动；进程消失后允许清理失效锁。独立 PID 不等于远程生成权限。
- `runtime/watchdog.status.json`：守护自身心跳、主流程心跳年龄与当前卡。
- `runtime/recovery-needed.json`：超时/失败恢复标记，只报告已有位置，不改写主流程状态。主流程恢复心跳后标记 inactive，保留历史警报事件。
- `runtime/controller.events.jsonl` / `watchdog.events.jsonl`：逐步进度与告警记录，写入失败时留有 `watchdog.errors.log`。

## 主流程命令

在本目录执行，或使用脚本绝对路径。相对产物路径以本目录为基准，全部产物必须位于 `卡牌归档` 内。

```powershell
python .\controller.py start
python .\controller.py begin <cardId> --artifact '..\生产底图\<cardId>.png'
# 调用一次内置图像工具；返回后立即把图保存到登记路径。
python .\controller.py artifact <cardId> '..\生产底图\<cardId>.png'
python .\controller.py touch --stage reviewing
# 完成视觉验收和单卡文档后提交。可同时登记图与对应任务记录。
python .\controller.py commit <cardId> '..\生产底图\<cardId>.png' '.\tasks\<cardId>.json'
python .\controller.py status
```

`begin` 应在生成前登记预期输出路径；意外中断后即使未运行 `artifact`，恢复时仍可找到已保存图片。`artifact` 只登记真实存在、非空的产物；`commit` 由主会话确认视觉与文档验收后调用，控制器只检查文件和 SHA-256，不冒充视觉验收。图像写入时主流程同样须拒绝覆盖已完成卡的文件，控制器不会替主流程写图。

发生失败运行 `python .\controller.py fail <cardId> --message '具体原因'`，保留当前卡与已有产物。需要长时间处理文档或检查时调用 `touch`；不启动自动心跳线程掩盖主流程停滞。

## 隐藏守护进程

```powershell
$taskDir = 'C:\Users\97349\Downloads\electron\卡牌归档\塔罗牌卡面\长任务'
$watchdogPath = Join-Path $taskDir 'watchdog.py'
$watchdogArgs = '"' + $watchdogPath + '" --timeout 900 --interval 15'
Start-Process -FilePath 'C:\Python314\python.exe' -ArgumentList $watchdogArgs -WorkingDirectory $taskDir -WindowStyle Hidden -RedirectStandardOutput (Join-Path $taskDir 'runtime\watchdog.stdout.log') -RedirectStandardError (Join-Path $taskDir 'runtime\watchdog.stderr.log') -PassThru
```

先 `start` 再启动守护；不要反复启动。任务完成/主动停工时执行 `controller.py stop`，守护下一次轮询退出并释放 PID 锁（通常15秒内）。如果在旧守护退出前重新 `start`，旧进程会继续监控，可沿用它。不要凭超时就杀掉正在等待生成返回的进程。

## 中断后恢复顺序

1. 阅读 `主任务.md`、`scope.json`、盘点与任务队列；检查 `controller.py status`，确认原主会话是否仍在运行，避免两个会话同时生成。
2. 核对 `currentTask.artifactCandidates`，已有图片先视觉验收；核对 `done` 的路径和哈希，完成产物不重做。
3. 明确接管后执行 `controller.py recover`。该命令刷新心跳、显示候选产物存在性与哈希，保留当前卡及 done，不自动将候选标为完成。
4. 已有合格图片时补文档再 commit；缺少/不合格时在当前卡继续生成并登记原因。只有当前卡提交完成后才 begin 下一张。
5. 用 `watchdog.status.json` 和 PID 判断监控是否存活；无守护时按上方命令启动。

隔离验证仅允许 `--runtime-dir` 指向本目录 `runtime/` 下的子目录，测试状态不得覆盖正式 state。守护机制保障已保存进度可续作，不保证一个生成调用绝不会被外部中断。
