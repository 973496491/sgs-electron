# 单卡执行协议

每个生成子任务只处理一项任务ID，使用新的独立上下文，不继承整批图像历史。父流程负责选择任务和controller.begin/commit；生成子任务负责一次任务的图像生成、落盘、视觉检查与单卡记录。

1. 主流程确定scope与规范，执行器只取指定任务字段和prepare给出的冻结提示词；首次使用工具按imagegen技能必要章节执行。不要回显整份队列、规范或历史记录。不得自行增加花色、改变牌名映射或用点数替代范围。
2. 使用production_io.py prepare取得单张压缩参考、提示词、唯一任务标签和目标路径。已有未提交产物先检查，不重复生成。

   如首张同花色或明确纠错需要对象级说明，`prepare --correction <短说明>`会把它冻结进该次提示词；已准备版本不允许换说明，需新attempt。不要把清区误当作逐像素移动，必要时明确删除整组内饰。
3. 用view_image加载这一张参考图，用内置imagegen生成一张。每次请求只有一个目标；不得改用CLI/API或并行多图请求。
4. 立即调用save保存原始结果及实际186×260交付PNG，默认只view这份交付PNG一次，检查文字顺序、花色、徽记、留位、完整框。仅关键内容确实不明确时查原像素局部；不固定生成或回读另一套预览图。
5. 生产底图不可固定左上点数和功能小花色；图层留位为186×260中的x8..46、y8..72。上中大花色、右上装饰小花色属于底图样式，可保留。
6. 检查通过后使用review记录具体检查结论，保存原始PNG、186×260导出、单卡JSON和Markdown。不合格时报告具体问题并使用独立attempt版本重试，绝不覆盖已提交的完成产物。
7. 返回精简结果：任务ID、文件绝对路径、是否通过视觉检查、生成ID、存在的问题。不要返回base64，也不要把其他已生成卡图附回主流程。
8. 主流程核对文件、检查点和检查说明后commit，更新总队列再领取下一张。共享矩形复用项仅在源卡完成后复制/映射并验证相同像素，不能另画成冲突内容。

主流程可用`progress.py accept-next <已review任务ID>`一次完成当前提交、高清导出、领取最早未完成项和同步检查点；只返回精简完成数/下一任务字段。调用后下一卡已begin，不要再次begin。单独`accept`与`sync`仍可用。这样减少逐卡重复命令与状态回读，不改变逐项验收门槛。

子任务、检查点和守护共同保证可恢复；不能声称单一图集替换已实现按花色选图。最终素材合并采用另行记录的交付方案。

## 请求体控制与重试（2026-10-21续作）

用户最新要求省token并改善186×260放大后的模糊：每卡只生成一张实际卡面，直接导出最大744×1040高清WebP（沿用`生产底图/压缩预览/<id>.webp`路径，≤200,000字节）与图集所需186×260无损PNG（同样≤200,000字节）。原始PNG只归档溯源，高清文件为实际查看用，不再另外制作展示卡、背景层、HTML或拼图。`progress.py accept/sync`仍同步必要高清文件与SHA，但不自动制作网页。原图正确而尺寸导出失败时仅恢复本地导出，禁止重发生成。既有网页是历史快照，后续准确进度看state/tasks，查看卡面直接打开高清文件。

- 每张卡使用 `fork_turns=none` 的独立子任务；每次重试也重新建立独立上下文，不携带前次原始PNG或整批历史。
- 生成前只载入 `prepare` 输出的一张参考JPEG（当前工具限制小于150 KB、最大465×650），只提交一个目标和该次唯一标签。父流程不读取或转发图片/base64。
- 原始PNG先落盘。不重复回传高清原图；默认只view一次交付PNG。`inspect`默认直接返回该PNG，不写新检查图；`inspect --detailed`仅在确有疑问时手动使用。
- 不通过时先 `review --reject` 写明问题，结束该次子任务；下一独立上下文使用新attempt和上一候选的压缩参考做定向修正。重试前仍先检索已有原生结果，避免重复生成。
- 父流程只接收任务ID、候选/生产文件路径、生成ID、验收结论和简短原因；通过后检查文件及记录再 `progress.py accept`，每张提交后才开始下一张。

排版规范中的文字块宽度百分比是设计目标，不是机械验收阈值。文字、顺序、花色、徽记、留位等硬性信息必须正确；在这些正确的前提下，按93×130可读性、主体重量与上下装饰间距判断。顺手牵羊方块v1曾仅因可见宽约47%低于约60%目标被退回，主流程复看后确认四字清晰、主体完整且有必要留白，已记录复核依据并接受；不可据此放行错字、过小难辨或拥挤的卡面。

普通杀和元素杀必须使用简体“杀”（U+6740，六画、上部交叉撇捺、下部木，无右侧“殳”）。方块普通杀v1曾生成繁体“殺”，已明确退回；v2使用v1小JPEG并以上述结构定向纠正后通过465×650及93×130检查。后续同为方块的火/冰/雷杀可优先用已提交的`生产底图/大图/Sha_png__diamond.png`作同花色净空参考，并按任务增加右下属性徽记。其他花色仍先保留本花色专属纹样，再引用准确简体字形要求，不能为复用字形而把方块装饰带入红桃/黑桃/梅花。

左上留位允许自然连续的低对比暗灰/暗红毛玻璃底纹，不要求机械纯色；禁止点数、功能花色、内侧金线悬饰和明显有边界的补丁。诸葛连弩方块v1的封闭椭圆黑心及暗红环边经两个独立上下文复核后退回，v2定向消除该圆斑并保留一般自然底纹后通过。原生工具返回成功不等于已经看见图片：若工具此次未展示原图，先保存并实际查看小检查图/必要原像素小裁切，再报告视觉结论；不能从提示词或成功状态推断缺陷已修复。

标题按完整字形与小图识别性验收，不能以独立连通块数机械判断多笔。简体“闪”的“门”本有一枚可与框分离的点/短斜笔，书法可位于框上方偏左。红桃闪v1经独立复核确有正常点之外的第二枚无归属短笔，v2只删额外短笔并保留正常第一点后通过；该例不授权删除其他“闪”字正常首点。
