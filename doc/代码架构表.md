## 八人身份场战绩标记链路 / 关键节点日志

主文件：`electron-next/resources/daxiaochao.user.js`

- 对局记录入口是 `ClientGameRecordInfoRep` 分支（`rn == J(730)`），先校验响应用户 ID，再按 `an.id` 是否属于 `[26,35,44,5,7]` 进入 `recGameRecord`；八人标准场对应 `modeId=5`。
- `recGameRecord(modeId, records)` 从每条记录读取 `figure -> shenfen`、`game_result -> result`、`used_general -> general`、`game_time/game_over_time`；只有 `game_result !== 255`、`used_general` 非空且时间键未重复时才保存。
- 新增 `[八人身份]` 日志：`message:game-record`、`record:received`、`record:item`、`record:accepted`。`record:item` 会记录 `figure`、`game_result`、`used_general` 数量、接受结果和拒绝原因；日志同时显示在调试窗口，并落盘到 `localStorage["xcEightIdentityTrace"]`（最多 200 条）。
- 新增轻量 `room-context` 日志：在房间 `ready` 和 `ClientGameRecordInfoRep` 节点只记录候选 `roomId/tableId/modeId/seatId/userId` 字段及少量相关字段名，不打印完整接口响应，因此不受接口响应 Worker/fallback 打印拦截影响；日志同样落盘到 `localStorage["xcEightIdentityTrace"]`。
- 当前最可能的失效点是入口过滤：响应中的用户字段、模式 ID 或记录字段结构变化时，代码会静默跳过；其次是 `game_result=255` 或 `used_general` 为空导致单条记录被丢弃。

关键词：`八人身份`、`ClientGameRecordInfoRep`、`recGameRecord`、`figure`、`shenfen`、`game_result`、`used_general`、`message:game-record`、`record:item`。

### 链路说明

1. 设置面板中的 `autoSQKSwitch` 存储键是 `AUTO_SQK_SWITCH`，`Id_Key_Value` 默认值为关闭（`!1` / `false`）。用户手动切到开启时，设置面板通用保存链路写入 `globalConfig.autoSQKSwitch`，并调用 `openAutoShouQiConfig` 用当前手牌触发 `CARD_CONFIG_VIP` 配置窗口；`openAutoShouQiConfig` 不再强制 `globalConfig.autoSQKSwitch = true`。如果还没找到初始牌，会提示发完初始牌后再配置。
2. `CardConfigWindow.btnOkHandler` 是目标手牌配置入口：
   - `globalState.configHandCards = this.handCardIDs`
   - `globalState.configHandCardsMode = this.sqkHandCardMode || "all"`
   - 关闭配置窗口后，如果当前展示的初始牌不满足目标，会立即模拟点击 `ShouQiKaAskWindow.useBtn`。
3. 配置窗口被补了两个确认模式：
   - `全部出现` -> `all`
   - `任一出现` -> `any`
4. `CardConfigWindow.SendClientChr1v1CardReq` 当前初始化自动刷牌窗口的三栏按钮：
   - 装备栏 `equipCardUIs`：`14` 连弩、`135` 古锭刀、`103` 丈八矛。
   - 锦囊栏 `jinNangCardUIs`：`64` 无懈、`6005` 拆/顺、`144` 兵、`32` 乐、`4300` 兵/乐、`6004` 锦囊、`12053` 伤害锦囊。
   - 基本栏 `basicCardUIs`：`327` 桃/酒、`25` 桃、`130` 酒、`2` 闪、`6` 任意杀、`7` 杀、`138` 属性杀、`112` 火杀。
   - `pushHandCardUis` 和 `ShowWindow("CardConfigWindow")` 分支会隐藏花色点数；如果按钮 ID 命中 `XC.sqkName`，会用 `AddCardTag` 标出分组名。
5. `XC.sqkName` 是窗口显示标签，`XC.sqk` 是命中判断展开表。当前重点分组：
   - `6` 任意杀 -> 杀 / 火杀 / 雷杀 / 冰杀。
   - `327` 桃/酒 -> 桃 / 酒。
   - `6005` 拆/顺 -> 顺手 / 过拆。
   - `4300` 兵/乐 -> 兵 / 乐。
   - `6004` 锦囊、`12053` 伤害锦囊、`196` 武器、`12148` 防具、`12130` 装备会展开成对应牌名集合；调整分组命中范围时改 `XC.sqk`，调整窗口按钮标签时改 `XC.sqkName`。
6. `checkHandCards(cards, target, mode)` 是命中判断：
   - 无目标牌时返回 `true`。
   - 自动发牌分支不会把空目标当作本轮刷牌成功；`globalState.configHandCards.length === 0` 时直接记录 `deal:wait-config` 并等待配置窗口确认，避免 `target:[]` 吞掉自动手气。
   - `all` 模式要求目标配置都能在当前手牌里匹配到。
   - `any` 模式只要任一目标匹配就返回 `true`。
   - 分组牌通过 `XC.sqk` 展开，例如 `任意杀`、`桃/酒`、`拆/顺`。
7. 发牌事件 `logic(...)` 中，初始发牌满足“牌堆 -> 自己手牌”的事件形态后，会延迟执行：
   - 如果 `globalState.configHandCards` 为空，记录 `deal:wait-config` 后返回，等待 `CARD_CONFIG_VIP` 配置结果。
   - 已有目标牌时调用 `checkHandCards(dn, globalState.configHandCards)`。
   - 未命中则点击 `laya.win("ShouQiKaAskWindow").useBtn.onMouse({ type: Laya.Event.CLICK })`
   - 当前实现已给 `ShouQiKaAskWindow` 和 `useBtn` 加空值保护，避免部分模式没有窗口时报错。
8. 调试窗口打开时，自动手气链路通过 `window.__xcAutoSQKDebugLog` 写入日志：
   - `config:init-toggle` / `config:toggle-action` / `config:switch-change`：设置面板初始化、用户切换开关、`globalConfig.autoSQKSwitch` 持久化变化。
   - `config:window-show` / `config:save` / `config:close`：`CardConfigWindow` 显示、确认保存目标牌、关闭窗口和 `configHandCardsRejected` 状态。
   - `config:post-check` / `config:click-useBtn` / `config:missing-useBtn`：配置保存后立即检查当前手牌，并记录是否找到 `ShouQiKaAskWindow.useBtn`。
   - `openConfig:start` / `openConfig:zoneCards` / `openConfig:uiCards`：设置面板主动打开配置时的当前开关、配置状态和手牌来源。
   - `openConfig:event` / `openConfig:window-probe` / `openConfig:fallback-show` / `openConfig:fallback-probe`：`CARD_CONFIG_VIP` 事件、配置窗口是否出现、以及 `laya.ged.ShowWindow("CardConfigWindow")` 备用路径结果。
   - `deal:start` / `deal:auto-config`：初始牌发牌分支进入自动手气时的开关、目标牌数量、拒绝状态和自动配置弹窗触发。
   - `deal:auto-config-disabled` / `deal:skip-auto-config` / `deal:timer-fired`：自动配置未触发的原因（开关关闭、已有目标、用户拒绝）和延迟检查实际开始。
   - `deal:event` / `deal:window-probe` / `deal:fallback-show` / `deal:fallback-probe`：发牌自动配置路径的事件、窗口探测和备用打开窗口结果。
   - `deal:wait-config`：`target:[]` / 空目标牌时等待配置，不调用 `checkHandCards` 结果驱动点击。
   - `deal:check` / `deal:click-useBtn` / `deal:missing-useBtn`：延迟判断结果、目标配置、窗口和按钮是否存在，以及是否实际点击 `useBtn`。
   - `check:no-target` / `check:hit-any` / `check:miss-all` / `check:done`：`checkHandCards` 内部命中细节，包含目标、模式、命中的分组或缺失项、剩余手牌计数。
   - `deal:skip-autoBotSwitch-11`：`globalState.autoBotSwitch === 11` 导致跳过自动手气时输出。

### 场景限制

历史版本中，自动弹出 `CARD_CONFIG_VIP` 配置窗口有白名单：

```js
room.isShanHeTu || room.isDouDiZhu || room.isRoguelike1v1
```

2026-07-15 已移除这个场景白名单。当前自动弹配置窗口仍然要求：

- `globalConfig.autoSQKSwitch` 为真。
- `globalState.configHandCards.length` 为 `0`。
- `globalState.configHandCardsRejected` 为假。
- `globalState.autoBotSwitch !== 11`。

自动弹窗和自动点击手气卡仍然依赖“牌堆 -> 自己手牌”的发牌事件形态。已有 `globalState.configHandCards` 时，后续自动点击手气卡主要受 `checkHandCards`、`autoBotSwitch !== 11` 和发牌事件形态限制。

新装或清空本地存储时，`AUTO_SQK_SWITCH` 默认关闭；已有本地存储仍尊重用户保存过的开关值。

### 链路说明

1. 调试窗口按钮入口是 `openDebugFromButton()`。开启时设置 `window.XC.isDebug = true`、打开 `#xcDebugPanel`，并主动调用 `installLocalSkinDebugResponseHook()` 安装接口监听。
2. `installLocalSkinDebugResponseHook()` 复用 `window.__localSkinDebug` 状态：
   - `state.printResp` 控制“接口打印”复选框，默认开启。
   - `state.respHook` 是挂到 `window.SGSMODULE` 的响应监听函数。
   - `state.respListenerPushed` 记录响应监听已创建；如果 `state.respHook` 被移出 `window.SGSMODULE`，再次打开调试会重挂。
   - `state.respHookRetryTimer` 用于等待 `window.SGSMODULE` 初始化，最多约 20 秒。
   - `state.dumpPostQueue` / `state.dumpWorkerBusy` / `state.dumpJobs` / `state.dumpActiveJob` 管理接口打印后台队列，确保一次只向 Worker 投递一个大响应。
   - `state.debugChunkQueue` / `state.debugChunkFlushTimer` 管理 DOM 分片写入，避免一次性插入超长文本节点。
   - `state.fallbackDumpQueue` / `state.fallbackDumpActive` / `state.fallbackDumpTimer` 管理不可克隆响应的分时主线程兜底遍历。
   - `state.responseIgnoreRules` 是当前接口打印拦截前缀列表，来自 `localStorage["xcLocalSkinDebugIgnoreRules"]`，未保存过时使用 `DEFAULT_DEBUG_IGNORE_RULES`。
   - `state.configPanelEl` 是调试窗口内的 `接口拦截配置` 面板。
3. 本地皮肤入口 `runLocalSkinEnableInline()` 内的 `installSgsModuleHook()` 也复用 `installLocalSkinDebugResponseHook()`，不再维护另一份响应 hook。
4. 接口打印匹配响应对象的 `className` / `WindowName` / `Protocol.className` / `Protocol.ProtoObj.className`；`ChangeSkinWindow` 窗口启动事件仍跳过。
   - `isLocalSkinDebugResponsePrintIgnored(cn)` 是接口打印黑名单；当前按 `state.responseIgnoreRules` 做响应名前缀匹配，默认过滤 `decodeSSCChatmsgNtf*` 聊天通知响应，命中后只跳过 Worker、fallback 和 DOM dump，不阻断 `pendingSkin` 替换。
   - 调试窗口头部 `配置` 按钮调用 `toggleLocalSkinDebugConfigPanel()`；配置面板支持“添加 / 删除 / 保存 / 打开配置文件 / 关闭”，编辑和删除只改当前面板，只有点击“保存”才调用 `saveLocalSkinDebugIgnoreRules()` 写入本地存储。
   - 已有规则渲染时继续调用 `addRow(rule)` 追加，保持已保存规则的显示顺序；点击 `添加` 时调用 `addRow("", true)`，通过 `list.insertBefore(row, list.firstChild)` 把新空行插到顶部，并设置 `panel.scrollTop = 0` 后聚焦输入框。
   - `打开配置文件` 调用 `openLocalSkinDebugConfigFile()`，优先通过 webview preload 暴露的 `window.daxiaochaoElectron.openConfigFile()` 请求主进程 IPC `open-config-file`；主进程确保 `app.getPath("userData")/config.json` 存在后用 `shell.openPath()` 交给系统默认编辑器，失败时 `shell.showItemInFolder()` 并把错误写回调试窗口。
   - 如果 `window.daxiaochaoElectron` 在 webview 页面主世界不可见，`openLocalSkinDebugConfigFileByAtom()` 会改用 `fetch("atom://open-config-file")`；fetch 不可用时再兜底 `window.open("atom://open-config-file")`，主进程的 `setWindowOpenHandler` 会拦截该 URL 并调用同一个 `openConfigFile()`。
   - `electron-next/src/electron/configFile.js` 是打开文件的共享实现；`ipcEvent.js`、`interceptor.js`、`main.js` 都只负责接入入口，避免三条通道行为分叉。
   - 主进程 / 协议处理改动必须重启 Electron 客户端后生效；只重新加载小抄脚本会继续使用旧主进程，可能仍然打不开配置文件。
   - 注意 `打开配置文件` 打开的是 Electron 外壳配置 `userData/config.json`；接口拦截规则仍保存在游戏页面 `localStorage["xcLocalSkinDebugIgnoreRules"]`，两者不要混淆。
5. 本地皮肤替换只在皮肤相关响应或实际含 `GeneralSkinList` 时处理 `pendingSkin`，避免无关接口触发 SkinID 替换日志。
   - `state.respHook` 不再记录 pending 期间的所有通知；只有响应名包含 `skin`、匹配 `GsCUpdateRoleDataExNtf` / `GsCUpdateRoleDataNtf`，或实际带 `GeneralSkinList` 时才处理候选，避免 `MsgActionStateNtf` 等普通通知刷屏。
   - 已兼容 `GsCUpdateRoleDataExNtf` / `GsCUpdateRoleDataNtf` 角色数据通知，并额外查找 `protoObj.GeneralSkinList`、`Data.GeneralSkinList` 和 `data.GeneralSkinList`；这是本地皮肤服务端通知不带 `skin` 字样时的关键入口。
   - 回归修复：响应对象可能只有 `GeneralSkinList` 而没有顶层 `className`，不能先因响应名为空直接返回；`respHook` 先取列表，再允许“有列表但无响应名”的候选进入本地皮肤替换。
   - 回归修复：`getLocalSkinDebugResponseName()` 不再使用泛化的 `first.name`，避免它遮蔽 `Protocol.className` / `Protocol.ProtoObj.className`，导致原本可识别的皮肤响应被判为普通响应。
   - 回归修复：`isLocalSkinDebugResponsePrintIgnored()` 只控制接口 dump，不再阻断 `pendingSkin` 的实际替换；被配置为不打印的响应仍必须参与 `GeneralSkinList` 修改。
   - 日志收敛：成功改写 `SkinID` 后立即清空 `state.pendingSkin`，避免后续每个皮肤响应重复打印同一候选链路；完整接口 dump 只在等待中的皮肤响应上入队。
6. 接口打印输出链路：
   - `state.respHook` 命中可打印响应后只调用 `queueLocalSkinDebugResponseDump(cn, first)`，不在接口回调里同步 `deepDumpLocalSkinDebug(first)`。
   - `processLocalSkinDebugDumpPostQueue()` 延迟处理队列；调试关闭或“接口打印”关闭时会清掉待打印响应。
   - `createLocalSkinDebugDumpWorker()` 优先创建 Blob Web Worker，在子线程完整 `JSON.stringify` 响应对象；循环引用输出 `[Circular]`，函数、BigInt、Map、Set、TypedArray 有可读兜底。
   - Worker 以约 64KB chunk 回传完整文本，`queueLocalSkinDebugBlockChunk()` 和 `flushLocalSkinDebugChunks()` 再按帧追加到同一个日志块；这是分片输出，不是长度截断。
   - Worker 不可用、异常或 `postMessage` 克隆失败时，`queueLocalSkinDebugFallbackDump()` 会加 `fallback-incremental:*` 标记，改由 `runLocalSkinDebugFallbackDumpStep()` 分时遍历对象；这条路径不再调用同步 `deepDumpLocalSkinDebug()`。
   - `processLocalSkinDebugFallbackFrame()` / `pushLocalSkinDebugFallbackValue()` 会完整展开普通对象、数组、Map、Set、TypedArray；函数、BigInt、undefined、Symbol、循环引用和 getter 异常输出可读占位。
   - DOM、`window`、`document` 无法结构化克隆且展开代价不可控，兜底输出 `[DOM ...]` / `[Window]` / `[Document]`，避免把页面运行环境整棵对象树写进调试窗口。
   - “清空”和关闭调试窗口都会调用 `stopLocalSkinDebugDumpWorker()` / `clearLocalSkinDebugPendingChunks()`，终止当前后台 dump 并清空待写 DOM 分片。
