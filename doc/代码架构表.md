## 八人场 PVE 自动显示身份链路

记录时间：2026-08-01

主文件：`electron-next/resources/daxiaochao.user.js`

- 实际显示执行器是 `laya.figureOut(source, attempt)`：从 `RoomControler.TableSetting/tableSetting` 读取 `IsChooseFigure`，从 `TabbleSeatInfos/tabbleSeatInfos.datum` 读取 8 个座位的 `ClientId/clientId` 顺序，再向 `gamescene.seatContainer.seatUIs[*]` 的身份状态写入 `[主公,忠臣,忠臣,内奸,反贼,反贼,反贼,反贼]` 对应值 `[1,2,2,4,3,3,3,3]`。
- 旧链只由 `laya.seatUIs()` 和 `laya.skills()` 单次调用 `figureOut()`；PVE 的 `TableSetting`、`TabbleSeatInfos.datum` 或 `seatUIs` 异步晚到时会静默跳过，且 `game.start()` 还受 `!game.isGameStart && room.size` 门槛影响。
- 新增 `scheduleEightPveFigureOut(source)`，在 `script.bootstrap`、`debug.open`、`room.ready`、`game.start`、自己的初始发牌 `deal:start`、`laya.seatUIs`、`laya.skills` 七个节点补触发；未就绪时每 300ms 重试，最多 30 次。每个新触发会先 `clearTimeout` 并替换旧重试链，避免场景生命周期清掉 timer 但本地仍保留真值句柄时，`if (timer) return` 永久吞掉后续入口。`script.bootstrap` 覆盖脚本中途注入或已经错过进房通知的情况。
- `ClientId/clientId` 匹配改为 `String(value) === String(clientId)`，兼容 PVE 座位表和 UI 一侧为数字、另一侧为字符串的情况；客户端 ID 缺失、`figureManager` 缺失或座位 UI 少于 8 个时继续有限重试。
- 场景限制保持原行为：只有 `IsChooseFigure` 为真且 `room.isDuanXian` 为假、`datum.length === 8` 时才写身份；显式 `IsChooseFigure=false` 和断线重连直接跳过。已有非零 `Figure` 不覆盖，避免改写服务端已公开身份。
- 实测新版 `figureManager.Figure` 是只有 getter 的只读访问器，直接赋值会抛出 `Cannot set property Figure ... which has only a getter`。写入链现按顺序尝试：descriptor setter、从 getter 源码恢复的 backing key、已知座位字段 `seat.figure`（`_0x3812(1087)`）、实例自有可写 `Figure` 数据属性；写后必须能从 `figureManager.Figure` 读回目标值才计为成功。
- 实测仅写 `figureManager.figureValue` 虽能读回身份，但身份图标仍不可见，并且后续 `skills` 生命周期会把七个隐藏座位重新刷成 `Figure=0`。显示链现先同步底层座位模型 `seat.figure`，再写 `figureManager` 状态；写完调用 `gamescene.rightView.UpdateFigureList()`（`_0x3812(1498/930)`），仅在公共入口缺失时回退 `__UpdateFigureList`（`_0x3812(246)`），同时对 `figureManager/seatUI` 调用 Laya `repaint()`。这样原生身份列表刷新能从非零座位模型重建图标，后续生命周期也不会再从空模型覆盖显示状态。
- 身份写入改为逐座位 `try/catch`，单个只读属性或对象异常不会中断整轮；`figure-out:result` 新增 `writeFailed`、`writeModes`、`figureDescriptor` 和最多 4 条 `writeErrors`。确定性的 `figure-write-failed` 在座位均已解析时不再重试 30 次刷屏。
- `figure-out:result` 的刷新诊断字段为 `modelSynced/modelSyncFailed/repainted/refreshFailed/rightViewRefresh/refreshErrors`；`rightViewRefresh` 成功值应为 `UpdateFigureList`（或兼容回退 `__UpdateFigureList`）。右侧刷新入口尚未就绪或调用异常时，scheduler 分别以 `figure-list-refresh-unavailable/figure-ui-refresh-failed` 有限重试。
- 原 `SetPlayNameVisible(ClientId < 4e9)` 姓名显示刷新仍在每次 `figureOut()` 开头执行，不受 PVE 身份门槛和提前返回影响。
- userscript 核心位于第一个 IIFE，调试窗口位于第二个 IIFE；核心不能直接引用后段局部 `appendLocalSkinDebugLine()`，否则 `ReferenceError` 会被空 `catch` 吞掉。第二个 IIFE 现在导出 `window.__xcAppendLocalSkinDebugLine`，核心 `logEightPveFigure()` 通过该桥输出 `[八人PVE身份] figure-out:wait/skip/result/timeout`；桥未就绪时最多暂存 50 行。
- 调度器另输出 `scheduler:start/invoke/result`：`start.replacedPendingTimer` 表示是否替换旧 timer，`invoke` 验证 `laya.figureOut` 是否存在，`result` 固定记录 `retry/reason/message`。即使 `figureOut()` 意外返回空值，也会转成 `figureOut-return-empty`，不再出现 `debug-open:dispatch` 后完全静默。
- 核心 `laya` 同样不在调试窗口 IIFE 的词法作用域；页面全局 `laya` 没有 `figureOut`，因此 v4 的 `localExecutorReady=false` 是作用域误判。核心现导出 `window.__xcRunEightPveFigureOut(source,attempt)` 执行桥。`openDebugFromButton()` 的 v5 探针输出 `debug-open:v5-dispatch`，通过执行桥直接调用真实 `figureOut` 并打印 `v5-direct-result/v5-direct-error`，再调用 scheduler 并打印其实际 `retry/reason/message`。
- 手动诊断入口为 `window.__xcScheduleEightPveFigureOut("manual")`。回滚整个功能时检索并移除 `scheduleEightPveFigureOut` 的七个补调用及调度器，同时把 `seatUIs/skills` 恢复为直接 `this.figureOut()`；只回滚刷新补丁时移除 `seat.figure` 模型同步、`repaint()` 和 `rightView.UpdateFigureList/__UpdateFigureList` 调用。回归重点检查身份图标可见、生命周期刷新后不消失、标准身份场不写入、断线重连不覆盖以及已有非零身份不被改写。

## 八人身份场战绩标记链路 / 关键节点日志

主文件：`electron-next/resources/daxiaochao.user.js`

- 对局记录入口是 `ClientGameRecordInfoRep` 分支（`rn == J(730)`），先校验响应用户 ID，再按 `an.id` 是否属于 `[26,35,44,5,7,1]` 进入 `recGameRecord`；八人标准对应 `modeId=1`，八人至尊对应 `modeId=5`。
- `recGameRecord(modeId, records)` 从每条记录读取 `figure -> shenfen`、`game_result -> result`、`used_general -> general`、`game_time/game_over_time`；只有 `game_result !== 255`、`used_general` 非空且时间键未重复时才保存。
- 新增 `[八人身份]` 日志：`message:game-record`、`record:received`、`record:item`、`record:accepted`。`record:item` 会记录 `figure`、`game_result`、`used_general` 数量、接受结果和拒绝原因；日志同时显示在调试窗口，并落盘到 `localStorage["xcEightIdentityTrace"]`（最多 200 条）。
- 新增独立 `interface-probe`：外层 `SGSMODULE` 监听按 `ClientGameRecordInfoRep` 类名或 `query_uid/all_record/used_general/game_result/figure` 战绩字段形态识别响应，强制向调试窗口输出 `query_uid`、`modeId`、`recordCount` 及 envelope/proto 字段摘要；不依赖全量接口打印开关或接口拦截规则，用于判断中央分发器之前是否已收到战绩响应。
- 上游请求入口是 `getseven(uid, modes)`：通过 `laya.get("SevenDayResultWindow")` 获取窗口，设置 `uuid`，再逐个调用 `sendReq(modeId)`。新增强制低频日志 `request:prepare`、`request:blocked`、`request:send`；窗口或 `sendReq` 缺失时明确记录并安全返回，避免请求端静默失效。
- 新增脚本级 `bootstrapEightIdentityRecordRequest()`：用于脚本重载时已经错过登录初始化或 `room.ready()` 的场景；最多等待 30 秒，待 `userID`、`SevenDayResultWindow` 和 `sendReq` 就绪后主动调用一次 `getseven()`。关键日志为 `bootstrap:wait`、`bootstrap:request`、`bootstrap:timeout`、`bootstrap:error`。
- 新增轻量 `room-context` 日志：在中央响应分发器、房间 `ready` 和 `ClientGameRecordInfoRep` 节点筛选房间/桌子/进房相关响应，只记录候选 `roomId/tableId/modeId/seatId/userId` 字段，不打印完整接口响应，因此不受接口响应 Worker/fallback 打印拦截影响；另有最多 40 个不同响应类名的 `dispatch-probe` 字段摘要用于定位混淆后的进房响应。日志统一写入调试窗口，并在调试开启时按既有链路落盘到 `localStorage["xcEightIdentityTrace"]`。
- `requestEnterRoom(t)` 是房间列表进入入口，参数 `t` 清洗非数字字符后作为请求进入的房间/桌号；新增 `room-enter-request` 轻量日志记录该 ID，不依赖接口响应打印。
- `game.start()` 作为发牌前的开局确认点新增 `game-start` 轻量日志；记录最近一次进房 ID、人数、`firstID`、`myID`、座位列表和模式标志，用于把进房请求与实际开局状态关联起来。
- `game.start()` 首次实际开局时按当前用户 UID 触发一次低频 `request:game-start` 战绩补请求，并用 `window.__xcEightIdentityRecordProbeUid` 去重；同时记录 `request:game-start-skip/blocked/error`，避免脚本初始化阶段的请求日志因调试窗口尚未打开而丢失。
- 由于部分版本不触发可拦截的 `game.start()`，`window.__xcAutoSQKDebugLog('deal:start')` 也作为稳定开局入口调用同一个按 UID 去重的请求探针，记录 `request:deal-start` 来源对应的请求生命周期。
- 请求探针不再跨作用域直接引用混淆局部变量；由 `getseven()` 和已有用户初始化链把 UID 写入 `window.__xcEightIdentityUid`，开局入口只读取该快照，避免 `_0x3cdad4 is not defined`。
- 开局探针检查战绩窗口时使用公开的 `window.laya.get("SevenDayResultWindow")` 和 `sendReq`，不再依赖作用域内的 `_0x47c207` 解码器。
- 开局探针确认窗口可用后直接设置 `uuid` 并调用公开的 `sendReq(modeId)`，不再从外层作用域调用依赖混淆解码器的 `getseven()`；每个模式单独记录 `request:send/request:send-error`。
- 若开局时 `sendReq` 尚未初始化，探针每 500ms 重试一次，最多 30 次；按 UID 只输出一次 `request:deal-start-blocked` 和一次 `request:deal-start-timeout`，重试过程静默，日志仅附带 `windowFound/windowClass/windowKeys` 窗口摘要，成功后清除 pending 与阻塞标记。
- 发牌分支在可访问游戏 `room` 作用域内先写入 `window.__xcLightRoomState` 快照；其中 `size/activeSeatCount` 表示当前已建立的活动座位数，不等于房间配置人数。自动手气统一调试日志函数收到 `deal:start` 后，先直接写入 `deal-start-v2` 最小日志，再读取该快照写入完整 `deal-start` 房间上下文，避免跨作用域直接引用 `room`。
- `ClientGameRecordInfoRep` 分支新增强制 `message:game-record` 结构探针，不依赖固定字段名；记录运行时 `protoKeys`、标量字段及数组长度，并附带已知的 `modeId`、`query_uid`、`recordCount` 候选值。结算模式判断以实际响应结构为准，不再用活动座位数或模式旗标推断 8 人场类型。
- 发牌确认点增加 `role-probe` 并行链路：在可访问的本地 `room`/座位对象中按当前 `myID` 搜索 `shenfen/identity/role/camp/faction/figure/general` 候选字段，只输出本人候选字段摘要并去重，不依赖结算或战绩页面。
- `room.ready(n)` 是开局房间/座位下发入口，`role-probe` 同时扫描其原始参数 `n`；与 `deal:start` 扫描并行，避免身份字段只存在于 ready 数据而未保留到 room 实例。
- 当身份字段名被混淆、`role-probe` 无候选时，输出限量去重的 `role-shape`，仅包含 room 顶层键、嵌套对象键和数组长度/首项键，用于恢复旧身份字段映射。
- 身份探针同时挂在已确认可执行的 `__xcAutoSQKDebugLog('deal:start')` 出口：发牌分支暂存当前 `room/cards` 后，由调试日志函数输出 `deal-hook-reached` 并调用 `captureEightIdentityDealEntry` 输出限量 `deal-entry-v3` 摘要；异常输出 `deal-hook-error/deal-entry-v3-error`。这样身份链与自动手气日志共用同一出口，不依赖前置独立日志调用、结算页或接口全量打印。
- 为避免身份附加日志出口被吞掉，`deal:start` 的同一条自动手气日志数据额外携带 `identityProbe`；该字段直接来自当前 `room` 的摘要扫描，身份链可先通过现有 `deal:start` 行确认是否进入。
- `__xcAutoSQKDebugLog` 对 `deal:start` 保留低频强制输出，即使 `window.XC.isDebug` 在结算链路移除后被重置，也不会吞掉开局身份诊断；其余自动手气日志仍受调试开关控制。
- 调试窗口面板在场景切换后可能被游戏 DOM 重建移除；`ensureLocalSkinDebugPanel()` 现在校验 `panelEl/panelBody` 是否仍挂在当前 `document`，发现旧节点脱离时清空引用并重建，避免日志写入不可见旧面板。
- `getseven()` 默认战绩请求列表和脚本重载补请求列表已加入 `modeId=1`；响应白名单同步加入 1。统计页历史嵌入模板通过 `recordHTML()` 返回值兼容补丁同步加入 `recordModes` 的 1 号入口和 `sfName[1]` 身份映射，确保八人标准战绩可在界面选择、统计和导出。
- 当前最可能的失效点是入口过滤：响应中的用户字段、模式 ID 或记录字段结构变化时，代码会静默跳过；其次是 `game_result=255` 或 `used_general` 为空导致单条记录被丢弃。

关键词：`八人身份`、`bootstrapEightIdentityRecordRequest`、`bootstrap:wait`、`bootstrap:request`、`bootstrap:timeout`、`getseven`、`SevenDayResultWindow`、`sendReq`、`request:prepare`、`request:blocked`、`request:send`、`ClientGameRecordInfoRep`、`interface-probe`、`ClassName`、`ProtoObj`、`query_uid`、`all_record`、`recGameRecord`、`figure`、`shenfen`、`game_result`、`used_general`、`message:game-record`、`record:item`。

### 场景限制

历史版本中，自动弹出 `CARD_CONFIG_VIP` 配置窗口有白名单：

```js
room.isShanHeTu || room.isDouDiZhu || room.isRoguelike1v1
```

2026-07-15 已移除这个场景白名单。当前自动弹配置窗口仍然要求：

- `globalConfig.autoSQKSwitch` 为真。
- `globalState.configHandCards.length` 为 `0`。
- `globalState.configHandCardsRejected` 为假。
- `globalState.autoBotSwitch !== 11`。

自动弹窗和自动点击手气卡仍然依赖“牌堆 -> 自己手牌”的发牌事件形态。已有 `globalState.configHandCards` 时，后续自动点击手气卡主要受 `checkHandCards`、`autoBotSwitch !== 11` 和发牌事件形态限制。

新装或清空本地存储时，`AUTO_SQK_SWITCH` 默认关闭；已有本地存储仍尊重用户保存过的开关值。

6. 接口打印输出链路：
   - `state.respHook` 命中可打印响应后只调用 `queueLocalSkinDebugResponseDump(cn, first)`，不在接口回调里同步 `deepDumpLocalSkinDebug(first)`。
   - `processLocalSkinDebugDumpPostQueue()` 延迟处理队列；调试关闭或“接口打印”关闭时会清掉待打印响应。
   - `createLocalSkinDebugDumpWorker()` 优先创建 Blob Web Worker，在子线程完整 `JSON.stringify` 响应对象；循环引用输出 `[Circular]`，函数、BigInt、Map、Set、TypedArray 有可读兜底。
   - Worker 以约 64KB chunk 回传完整文本，`queueLocalSkinDebugBlockChunk()` 和 `flushLocalSkinDebugChunks()` 再按帧追加到同一个日志块；这是分片输出，不是长度截断。
   - Worker 不可用、异常或 `postMessage` 克隆失败时，`queueLocalSkinDebugFallbackDump()` 会加 `fallback-incremental:*` 标记，改由 `runLocalSkinDebugFallbackDumpStep()` 分时遍历对象；这条路径不再调用同步 `deepDumpLocalSkinDebug()`。
   - `processLocalSkinDebugFallbackFrame()` / `pushLocalSkinDebugFallbackValue()` 会完整展开普通对象、数组、Map、Set、TypedArray；函数、BigInt、undefined、Symbol、循环引用和 getter 异常输出可读占位。
   - DOM、`window`、`document` 无法结构化克隆且展开代价不可控，兜底输出 `[DOM ...]` / `[Window]` / `[Document]`，避免把页面运行环境整棵对象树写进调试窗口。
   - “清空”和关闭调试窗口都会调用 `stopLocalSkinDebugDumpWorker()` / `clearLocalSkinDebugPendingChunks()`，终止当前后台 dump 并清空待写 DOM 分片。
