## 结论与入口

百出使用原生的技能文字标签链，可供小抄参考：

```text
GsCUpdateRoleDataExNtf(IsSpell=true, DataID=3338)
  -> ServerProxy_GsCUpdateRoleDataExNtf
  -> BaiChu.UpdateRoleDataResponse -> markSkills

手牌刷新 PrivateUpdateCardUis / skillOrStateDataChange
  -> skillCardLabelChange(ui, skill, true)
  -> seat.SetCardUIRemark(ui.Card)
  -> BaiChu.SkillCardRemark(card)
  -> card.AddCardTag(text) -> card.TagArr1
  -> ui.IsSkillChangeStatus(true, text) -> ui.UpdateTag()
  -> cardTagBtn / cardTagBtn2 -> layoutTagUI()
```

上面分别列出数据写入与牌面重算两个入口。`skillOrStateDataChange` 监听 `SKILL_STATE_DATA_CHANGE`，`PrivateUpdateCardUis` 负责日常选牌/非选牌刷新；百出自身的 `UpdateRoleDataResponse` 没有直接派发该全局事件，不应编造“每条百出通知直接派发该事件”的调用关系。

原生另有 `ui.AddCardTag(text) / ui.DelCardTag(text)` 临时标签链，写的是 `ui.tempCardTag`，不是 `Card.TagArr1`。两者方法名相似，但对象和显示槽位不同。

## 百出的配置与数据语义

- `character.json`：`a=573,b=荀攸,ai=族,d=XunYou,j=3338,k=3166`；`cha_spell.json`：`a=3338,c=百出,d=BaiChu`。该快照 `this.r("BaiChu",xSi)`，`xSi extends $Kt`。
- 协议 `GsCUpdateRoleDataExNtf` 对应 `yO`，新协议号 `108018`，旧表 `21252`，字段为 `SeatID/IsSpell/DataID/data_count/Datas`。protobuf 适配来自 `seat_id/bspell/id/datacnt/data`。技能状态按 `DataID=3338` 查找，不是把它当成带 `SpellID` 的用牌通知。
- `ServerProxy_GsCUpdateRoleDataExNtf` 在 `IsSpell` 时按座位取 `GetGeneralSkill(DataID)`，回退技能实例工厂，再调用 `UpdateRoleDataResponse`。百出 `RetainRoleDataExLastParams=false`，因此当 `Datas.length>1` 时，分发器会在调用技能前 `Datas.pop()`。解析原始通知必须确认观察点在处理前还是处理后，不能重复剥离末尾项。
- 百出回调在 `IsSpell && Datas.length>3` 时清空 `markSkills`；若首项大于 0，从下标 1 开始每三项记录一组 `[牌名技能ID, 原始牌类型, 花色]`。这是技能记录，不是实体牌号列表。移除效果调用的第三参数为真时也清空记录。
- 随后执行 `seat.UpdateState(DATA_BAICHU=385, markSkills.length, markSkills)`；该长度是扁平数组长度，不能直接当记录张数。`DATA_BAICHU` 对应座位状态类 `TI`，点击状态打开 `BaiChuCardWindow`，这条座位图标/记录窗口链与牌面标签链不同。
- `SkillCardRemark(card)` 对非虚拟牌逐组三元记录扫描，每组先比较 `card.FirstSkillId`，命中即标记“百出”；再比较 `card.CardOriginTypeWithAvatar + card.FlowerOnSeat`，命中即不显示标签；整轮没有命中则返回 `BaiChu_Tag="新组合"`。源码在首次命中时 `break`，不要改写为无条件先扫描全部牌名、再扫描全部组合。

## 原生渲染与生命周期

`seat.SetCardUIRemark(card)` 的实际顺序：

1. 清空 `card.TagArr1`。
2. 遍历已开启、支持牌面文字的座位状态，取 `CardStateCardWords(card)`。
3. 遍历主将和副将的技能，取 `SkillCardRemark(card)`。
4. 将非空文字经 `card.AddCardTag()` 加入数组，返回 `TagArr1.join("")`。

`Card.AddCardTag` 对文字去重并按 `localeCompare(...,"zh-CN")` 排序。牌 UI 的 `UpdateTag()` 实际只将前两项分别写到 `cardTagBtn` 和 `cardTagBtn2`，第三项及后续项不会自动生成更多标签。返回的拼接字符串本身不是渲染结果。

`getCardTagBtn()` 使用 `card_tag_bg`，`layoutTagUI()` 将标签从牌底往上排；平面渲染路径经 `addDrawChild` 进入 `textureContainer`。直接调用原生 API 可复用这些排版和绘制差异。

`skillCardLabelChange` 受卡牌变身/技能换牌面分支约束，不是每次都会调用 `SetCardUIRemark`。手牌、木牛牌调用时传 `true`；额外牌、虚拟牌传 `false`，不能把手牌重算行为推广到所有选牌弹窗和装备 UI。

临时标签链为：

```text
ui.AddCardTag(text)
  -> tempCardTag 去重加入
  -> drawTempCardTag()
  -> cardTagBtn3.label = tempCardTag[0]
  -> layoutTagUI()
```

- `ui.DelCardTag(text)` 只删除匹配文字并重绘；`ui.AddCardTag("")` 清空全部临时标签。
- 临时数组也只有第一项可见，多个临时标签不会全部排出来。原生 `UpdateTag()` 清除技能标签时，不会顺带清空临时标签。
- 牌 UI 的 `Clear()` 清空 `tempCardTag` 并隐藏三个按钮；牌移走、UI 对象回收/重建后，需要按自己的状态重新附加。
- 还有座位级入口 `seat.addCardTag(ids,text,cardType=0)`：写已展示牌的 `Tag`，派发 `SEAT_CARD_ADD_TAG`，经本人 UI 的 `SeatCardAddTag -> cardContainer.addCardTag -> ui.AddCardTag`。`cardType=0/1/2` 分别选手牌/额外牌/虚拟牌 UI 数组；不凭空创建未知牌面。删除事件为 `SEAT_CARD_DEL_SPECIAL_TAG -> SeatCardDelSpecialTag -> delCardSpecialTag`。
