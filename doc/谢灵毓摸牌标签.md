# 谢灵毓心幽 / 元嫡摸牌来源标签

实现与核验日期：2026-10-08。源码：`electron-next/resources/daxiaochao.user.js` 的 `logic()`；测试：`electron-next/tests/visible-card-chain.cjs`；手工索引：`manualLookupNotes.xieLingYuDrawTags`。

## 最终行为

- 现有 `cardLabelSwitch` 开启时，本人因心幽 `4016`、元嫡 `4015` 从牌堆摸到的已知牌，分别显示 `[心幽]`、`[元嫡]` 来源标签。标签字符串沿用原有零宽前缀 `\u200b`，屏幕只显示括号和技能名。
- 复用小抄已有 `laya.mark -> ui.AddCardTag -> tempCardTag -> cardTagBtn3`，不另建技能缓存、配置开关、协议请求或轮询。原生技能的 `Card.TagArr1` 不被此次功能改写；百出同类技能标签仍有独立槽位。
- 标签表示牌的取得来源，不等于“当前不计入手牌上限”。回合结束不主动清除来源文字；牌 UI 的原生 `Clear()` 会清空临时标签，正常移出手牌和 UI 回收沿用这一生命周期。完整 UI 重建/重连没有独立来源缓存可以回填，切换开关也不追溯已经错过的摸牌。
- 本次已实现并通过源码抽取回归，未取得两技能实战消息；仅在服务端实际给出下述字段时命中，不根据技能发动时间窗口猜测后续所有摸牌来源。

该快照 `XinYou` 注册到 `nhi extends $Kt`，只设置主动弃置选牌条件，未覆盖 `SkillCardRemark` 或建立“心幽牌号表”；`$Kt` 继承 `_Xt.SkillCardRemark()` 的空返回。`YuanDi` 注册到 `ahi`，其技能状态维护的是牌名记录，不应当作本次摸到的实体牌号。

`GsCUpdateRoleDataExNtf(IsSpell=false,DataID=21)` 是通用 `OPT_DATA_DISCARD_IGNORE`：客户端把 `Datas` 赋给 `seat.DiscardIgnoreCards`，setter 派发 `SKILL_STATE_DATA_CHANGE`（事件值 `CARD_LABLE_STATE_CHANGE`）。getter 只在 `roundState>=DISCARD && InOwnRound2` 返回列表，出牌阶段可返回 `null`；`clearSkillState` 在 INIT/CLEARUP 等清理阶段清空底层列表。因此它既不能在出牌阶段稳定提供心幽来源，也不能区分由其他技能带来的免弃牌。本实现不使用它推断来源。

## 实际接入与原有漏项

既有来源标签条件为 `cardLabelSwitch && ToZone=5 && ToID=myID && SpellID && MoveType>1 && MoveType<255`。普通摸牌 `MoveType=1` 被排除，所以心幽和元嫡原本不会进入这条标签链。

此次只新增 `xieLingYuDrawName`：

```text
SGSMODULE -> main -> logic -> PubGsCMoveCard
  -> 既有非发送/非零数量/有效移动门槛，混合明暗牌按原逻辑处理
  -> MoveType=1 && FromZone=1 && SpellID 为 4016 或 4015
  -> cardLabelSwitch && ToZone=5 && ToID=room.myID
  -> 只取实际收到的正整数 CardIDs
  -> laya.mark(ids, "\u200b[心幽]" 或 "\u200b[元嫡]")
  -> setTimeout -> cardContainer.getCardUiBy -> ui.AddCardTag
  -> tempCardTag / drawTempCardTag / cardTagBtn3
```

- 标签名用已核实的心幽/元嫡常量，即使小抄技能字典暂缺该新技能条目也可显示。`SrcSeatID` 不作为牌的持有者，按 `ToID` 判断本人。
- 普通无技能摸牌、其他技能的 `MoveType=1`、其他座位、发送消息、心幽弃牌成本不新增标签；不扩大到 `FromZone!=1` 的同类型回流。原有非摸牌来源标签及来源玩家文字仍走原分支。
- 零占位、空牌号以及被现有混合明暗处理清空的牌号不标记，不使用记牌推测结果填补未知牌。正整数过滤创建新数组，不修改消息原 `CardIDs`。
- `laya.mark` 是 `laya.seatUIs()` 中绑定到当前本人容器的已有函数；它延迟查牌 UI，查不到时跳过。其第三个“匹配器”形参在当前实现中没有用于删除或替换文字，不应据此声称支持任意标签替换。
- `ui.AddCardTag` 使用临时标签槽，只显示 `tempCardTag[0]`；已有临时标签可能占用该槽。本次保留原生与现有小抄标签，不清空他人标签，也未改顺机/弹雀/炁的挂钩。
- 调试开启时，既有 `[可见牌] event:done` 的步骤增加 `drawtag:queue`，附带实际牌号及“心幽/元嫡”原因。它表示已调用标记入口，不声称 UI 此刻已绘制。日志仍经 `appendLocalSkinDebugLine()`，关闭调试不影响功能。
