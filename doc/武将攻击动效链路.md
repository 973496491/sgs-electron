# 武将攻击动效链路

核验日期：2026-10-15。对象为本地保存的 2026-10-08 OL ES6 官方客户端快照。第 1–6 节记录首次调查，经过静态源码核对、配置解密和抽取方法模拟验证，未在游戏内播放验证，也未下载动画文件。用户随后确认新增“皮肤屏蔽”开关，实现与验证记录在第 7 节；未热注入运行客户端或生成 asar。

## 1. 已找到的主链：动态皮肤攻击动作 GongJi

```text
PubGsCUseCard（新协议 108010 / 旧协议 21210）
  -> ServerProxy_PubGsCUseCard(event)
  -> GetSeat(protocol.SeatID)
  -> seat.ShowUseCardAni(protocol.CardID, protocol.useType)
  -> seat.event("USE_CARD", [CardID, useType])
  -> 座位 UI 的 addSeatListener -> useCardAniPlay(CardID, useType)
  -> onPlayNewSpEffect(3)                 // NEW_SKIN_PLAY_TYPE_sha
  -> GetGeneralSkinBySkinID(seat.SkinItemID)
  -> skinVo.DynamicSkinBigSkeletonUrlNew(seat.DySkinType, true)
  -> playingNewSpEffect.InitEffect(base + "/xingxiang.json", "GongJi", false)
  -> playingNewSpEffect.playEffect()
  -> Spine 模板加载 -> 校验动作名 -> Laya.SpineSkeleton.play
```

- 消息类是快照中的 `FQt`，`pbToOldProtocol` 将 `srcSeatId/cardId/spellId/usetype` 映射为 `SeatID/CardID/spellID/useType`；`data` 按 `destCnt/paramCnt` 拆为 `DestSeatIDs/Params`。不是 `MsgGamePlayCardNtf`，后者在该快照只有 `Param/cardCount/CardList`，不应按名字猜作此入口。
- 对战管理器快照符号 `bZt` 在 `ServerProxy` 上注册 `PUB_GS_C_USE_CARD -> ServerProxy_PubGsCUseCard`。处理函数要求座位、牌实例及牌的 `FirstSkill` 存在，随后调用 `ShowUseCardAni`。
- 座位模型快照符号 `Gts`；共用座位 UI 基类为 `xQt`，用 `addSeatListener/removeSeatListener` 对座位上的 `USE_CARD` 绑定/解绑 `useCardAniPlay`。这些混淆类符号仅供快照检索，不能作为运行时稳定类名。
- 这条调用只传动画类型 `3`，没有把 `DestSeatIDs` 传给 `onPlayNewSpEffect`；现有攻击出框位置依据自己/其他座位及屏幕位置计算，不能把它直接理解为跟踪指定目标的弹道。

## 2. 哪些牌会触发，哪些情况不播放

`useCardAniPlay` 用 `Card.GetInstance(CardID, false).FirstSkillId` 分类，并先检查当前皮肤 `NewSkinJudge` 为真、`IsChuChangOnlyDySkin` 为假。

| 条件 | 动画类型 | xingxiang.json 中的动作 |
|---|---|---|
| `FirstSkillId == SHA && useType == 1` | `NEW_SKIN_PLAY_TYPE_sha = 3` | `GongJi` |
| `FirstSkillId == NANMAN / JUEDOU / WANJIAN` | `3` | `GongJi` |
| `FirstSkillId == WUZHONG / WUXIE / HUOGONG` | `NEW_SKIN_PLAY_TYPE_hudong = 1` | `HuDong` |
| 其他牌，或杀的 `useType != 1` | 不从此方法触发 | — |

此处只确认 `useType == 1` 的源码条件，不据此推断所有协议场景下的业务含义。南蛮/决斗/万箭分支不要求 `useType == 1`。该方法即使命中并调用播放，也返回 `false`，不能用它的返回值判断是否播放成功。

`onPlayNewSpEffect` 还有这些必要条件：

1. `GameContext.ShowGameSkinEffects` 为真。快照的 getter 是 `!配置.NoShowGameSkinEffects || SettingManager.SystemSets.EffectSwitch`，不是只看设置中的一个开关。
2. `seat`、`seat.General` 存在，且 `seat.General.IsDynamic` 为真。
3. 当前没有 `playingNewSpEffect`；已经播放时直接早退，不在此方法中排队或打断重播。
4. `GetGeneralSkinBySkinID(seat.SkinItemID)` 有结果且 `NewSkinJudge` 为真。
5. 不是仅出场动态皮肤：`IsChuChangOnlyDySkin` 对应 `newSkinJudge === 103`。

这证明的是新版动态皮肤的攻击动作链，不代表所有静态皮肤、所有老动态皮肤或所有武将都具有 `GongJi`。

## 3. 皮肤配置和资源路径

配置文件：`cha_gs_dbs_fs_skininfo.sgs`，普通 AES-CFB 解密/gzip 后为 JSON。管理器配置名 `GeneralSkin_json`，`FileName="cha_gs_dbs_fs_skininfo"`。

- `root.abbreviation.field`：`a -> skinID`、`b -> generalID`、`c -> skinname`、`r -> restype`、`ab -> newSkinJudge`。
- 皮肤条目在 `generalskin.items.item`。
- 专用参数在 `generalskin.speciaSkin`，拼写确实是 `speciaSkin`；管理器 `initSpecialSkin -> GetSpecialSkinById`，以字符串 `skinID` 索引。
- `seat.SkinItemID` 来自座位的当前皮肤，`seat.DySkinType` 来自当前武将形态。不要直接以武将 ID 或商城物品 baseID 拼动画地址。

PC 分支 `DynamicSkinBigSkeletonUrlNew(state, inGame)` 的路径规则：

```text
rootResouceUrl + "res/runtime/pc/" + miniGamePath
  + "animate/" + resourceFolder + "/" + skinKey

resourceFolder:
  默认                             skinEffectNew
  专用配置 IsNewEffect && inGame    skinEffectSmall
  专用配置 IsNewEffect && !inGame   skinEffectBig

skinKey:
  单形态                           skinID
  IsManyStateDyskin                 skinID + "_" + state

攻击动作入口文件：base + "/xingxiang.json"
动作名：GongJi（大小写敏感）
```

`IsNewEffect` 是专用配置 `isNewEffect == 1`。`miniGamePath` 在 `layapcopen` 的位标记及 `IsLayaMobilePcWeb` 命中时是 `layaweb/`，通常为空；移动端另有 `spine/.../{0}/{0}.skel` 分支，不能套用上述 PC 地址。这里确认的是客户端生成的入口 URL；图集、纹理等资源依赖仍需沿引擎解析和实际文件继续核对。

同一份配置中的例子：

| skinID | 配置皮肤名 | newSkinJudge / restype | PC 局内攻击入口（相对资源根） |
|---|---|---|---|
| `35701` | 龙骧赫天*SP张郃 | `1 / 3` | `res/runtime/pc/animate/skinEffectNew/35701/xingxiang.json` |
| `700804` | 绵丽春暖*羊徽瑜 | `1 / 3` | `res/runtime/pc/animate/skinEffectNew/700804/xingxiang.json` |
| `59302` | 万军取首*谋关羽 | `1 / 3` | `res/runtime/pc/animate/skinEffectSmall/59302/xingxiang.json` |

上表是按配置和 PC 路径规则推导的地址，未联网确认这些文件当前存在或包含 `GongJi`。`59302` 的 `speciaSkin.isNewEffect=1`，其 `zoom=130`、`outPlace="-20,30"`、`atackPlace="600,300"`；资源目录不能一律写成 `skinEffectNew`。

## 4. 播放、事件、声音与恢复

播放器快照符号 `$F extends Laya.SpineSkeleton`：

```text
InitEffect(url, name, loop, autoDestroy = true)
  -> 记录 effectUrl / nameOrIndex / loop，并增加资源引用
playEffect()
  -> 已初始化：onPlaycheck -> play
  -> 未初始化：aB.GetInstane().LoadAnimate(url, this, ...)
     -> new Laya.SpineTemplet(Laya.SpineVersion.v4_0)
     -> loadAni(url, ...)
     -> SPINE_LOAD_COMPLETE -> onAnimateLoadComplete -> init(template)
     -> onCheckAnimHasName("GongJi") -> play("GongJi", false)
```

- 资源加载器 `aB` 按 URL 缓存、合并等待者、处理失败并引用计数释放。缺少动作名时派发 `PLAY_NAME_LOSE`；座位 UI 的 `onPlayNameLoseComplete` 会调用收尾。仅有目录/配置不能证明动作存在。
- `onPlayNewSpEffect` 同时创建 `playingNewSpEffect` 和 `newFullScreenEffect`。后者初始化 `base + "/quanping.json" / "QuanPing"`，但此处不立即播放，要等动作的 `quanping` 标签。
- `Laya.Event.LABEL -> aniEventNew`：`ChuKuang` 调整出框位置；自己座位的攻击偏移读 `AtackPlace`（配置字段拼作 `atackPlace`），其他座位按场景左/右半区定位。此处专用配置实际使用 `NewJudgeSkinID(1)`，不要误写成总是当前形态。
- `zhenping -> CurrentScene.PlaySimpleShakeEffect()`；`quanping -> newFullScreenEffect.playEffect()` 并缩放至场景；`Skill` 可接 `jineng02.json` 的技能/受击扩展分支，单独的攻击入口未传技能事件参数。
- `fF.PlaySkinSoundByLabel` 监听 `ChuChang/GongJi/JiNeng/HuDong` 的标签，遇到以 `audio` 开头的名字后播放 `animate/<skinID>/<小写标签名>` 对应音效。
- `onLoadSpineComplete` / `onPlayNameSucComplete` 通过 `SHOW_NEW_BIGSKIN_EFFECT(false, skinKey)` 隐藏原展示。`STOPPED -> aniNewcallBack` 停止并清空 `playingNewSpEffect`，派发 `SHOW_NEW_BIGSKIN_EFFECT(true, skinKey)` 恢复展示；有待执行形态转换时继续 `onShowDoubleSkinJuexing`。播放器自身默认的 `autoDestroy` 负责单次播放后的销毁；全屏效果另有 `aniFullscreenBack/clearNewFullScreenEffect`。

## 7. 已实现：皮肤屏蔽开关

用户明确要求新增名称“皮肤屏蔽”，提示“屏蔽局内皮肤特效”，并澄清摆放为“屏蔽弹幕后面，卡牌标签上面”。已按这一布局接入 userscript：屏蔽弹幕右侧、同一行，卡牌标签上方、同一列；原有明牌框框位置保持。

### 开关与挂钩

`installSkinEffectButton -> xcSkinEffectToggle -> __xcSetSkinEffectsBlocked -> setSkinEffectsBlocked`。本地键 `xcSkinEffectsBlocked`，首次/非法值/读取失败默认关闭；`xc-skin-effects-change` 同步按钮。独立于其他屏蔽设置，关闭时按原生逻辑和原有特效开关执行，不补播已跳过动作。

核心 `installSkinEffectBlocker` 沿 `laya.gamescene.SelfSeatUi`、`seatContainer.seatUIs` 定位实例并逐级找真实原型，按原型+方法幂等包装。初版只拦 `onPlayNewSpEffect(type===3)`；用户反馈部分皮肤漏拦后，已修为新版 `1/2/3/5 -> HuDong/JiNeng/GongJi/JiNeng02` 以及旧版专属技能两段链，详见下面“漏拦原因与旧版链”。关闭时原 this、完整参数、返回值透传；普通出牌/结算、普通技能名提示/语音、待机及 `ZhuanChang` 形态切换继续原生逻辑。

### 播放中开启与异步加载

`clearVisibleSkinEffects -> clearBlockedSkinAnimation` 处理新版 `playingNewSpType` 为 1/2/3/5 的对象：

1. 捕获当前攻击及全屏层引用，先清理旧全屏层，取消其监听并销毁。
2. 对仍存在的攻击播放器调用原生 `aniNewcallBack`，清空忙碌状态并通过 `SHOW_NEW_BIGSKIN_EFFECT` 恢复原展示。
3. 销毁捕获的旧攻击播放器。不能只 stop，否则尚未完成的 Spine 加载仍可能继续触发显示/隐藏回调。
4. 原生收尾可能立即进入 `needPlayChange -> onShowDoubleSkinJuexing`，创建新的 `ZhuanChang` 与全屏层；清理只能针对事先捕获的旧引用。主动作已结束、全屏层仍残留的情况也单独处理。

旧版先通过 `clearLegacySkinAnimation -> clearOutAvatarAni` 销毁 `outAvatarEffect`，取消计时器及 STOPPED/LABEL 回调并恢复 `seatAvatar.ShowSkeleton(true)`。已经进入第二段的播放器没有统一字段，`clearSkinSkillChildren` 从当前游戏场景、各座位的 `effectSprite`、PromptLayer 的直属子节点筛出皮肤专属技能 URL，再销毁它们。只识别 `animate/spine/skillEffect/<皮肤>/<技能>/jineng0N.sk/json/skel` 以及 `skinEffectNew/Small/Big/<皮肤>/jineng02`，保留普通 hit、背景、待机、转场，并不遍历皮肤详情窗。

异常按座位隔离；若原生收尾未完成且当前没有新播放器，使用已捕获的皮肤/座位信息尝试恢复原展示。新增诊断前缀 `[皮肤屏蔽]`，仍走 `appendLocalSkinDebugLine(...,false)`，遵守调试窗口开关。
