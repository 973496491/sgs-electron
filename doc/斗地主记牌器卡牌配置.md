# 斗地主记牌器卡牌配置

## 结论

面板代码位于 `electron-next/resources/daxiaochao.user.js` 的斗地主记牌器链路（彩虹表解码器 `_0x138e`）。面板显示的卡牌对象来自游戏事件中的 `data_cards`，名称不是从固定名称字典按 ID 查出，而是按以下字段推导：

- 卡牌 ID 字段优先级：`cardId` -> `CardId` -> `card_id` -> `id` -> `ID`。
- 点数字段优先级：`CardNumber` -> `cardNumber` -> `rank` -> `number` -> `point` -> `Point`。
- 花色字段优先级：`Color` -> `color`。
- 如果事件对象没有点数，先按 `CardId` 推导：`CardNumber = floor(CardId / 100) % 100`，`Color = floor(CardId / 10000)`。
- 花色编码：`1=♠`、`2=♥`、`3=♣`、`4=♦`。
- 点数编码：`3..10` 显示为数字，`11=J`、`12=Q`、`13=K`、`14=A`、`15=2`、`16=SJ`、`17=BJ`。
- 大小王不显示花色：`1600=小王`、`1700=大王`。
- 面板牌面文本由 `rank + suit` 拼接；所以例如 `11400` 代表 `A♠`，`41500` 代表 `2♦`。事件中的 `CardId` 仍原样保留并作为追踪集合的键。

## 记牌器使用链

1. `_0x12d436` 从事件卡牌对象读取名称、点数或牌号；大小王也支持 `big/red/joker` 与 `small/black/joker` 等资源名兜底识别。
2. `_0x53632c` 仅在缺少结构化字段时按数值 `CardId` 拆出 `CardNumber` 与 `Color`。
3. `_0x372eff` 组装 `{index, cardId, color, rank, suit, text}`，其中 `text` 即面板使用的牌名。
4. `data_cards` 经过 `_0x26c5ba` 分区，按 `areaId` 生成各座位明牌/暗牌区域；`card_id` 是移动事件中的原始 ID。
5. `_0x3a39e2` 以 `seenIds` 统计已见牌，并从基础 54 张配置生成各点数剩余数量；数量为 0 时面板标记为缺失，数量达到 4 时标记警告。

## “杀 / 连弩 / 藤甲”这类卡牌名称关系

存在第二套“卡牌 ID -> 卡牌名称/类型”关系，不能与上面的斗地主基础牌 ID 拆解规则混用：

- `allCard`（源码变量 `_0x5984e1`）是面板使用的卡牌配置代理；缺少缓存项时，会从运行时卡牌配置表 `w[525]` 读取 `{name, type, color, number, subType}`，再按配置表的键保存。
- `Qcard.add(id)` 通过 `allCard[id]` 取得名称，因此面板可以显示 `杀`、`连弩`、`藤甲` 等名称；这不是由 `floor(id / 100)` 推导出来的基础牌面名称。
- 本地已确认的静态样例：`7 -> 杀`、`14 -> 连弩`。其中 `14 -> 连弩` 也出现在 `CardConfigWindow.SendClientChr1v1CardReq` 的装备按钮配置中。
- `藤甲 -> 名称` 的关系确实存在于同一类运行时 `allCard` 配置中，但当前仓库只保存了配置读取链，没有保存该版本运行时表中对应的具体数值键；因此文档不虚构一个未经本地数据确认的藤甲 ID。

这套关系应记录为：

```js
const DDZ_NAMED_CARD_CONFIG = [
  {id: 7, name: '杀', source: 'allCard / w[525]'},
  {id: 14, name: '连弩', source: 'allCard / w[525]'},
  {id: '<运行时配置键>', name: '藤甲', source: 'allCard / w[525]'}
];
```

后续若要补齐 `藤甲` 的数值 ID，应从运行时 `w[525]` 或实际 `data_cards`/移动事件对象中读取并记录；不要用基础 54 张牌的 `CardId` 公式反推。

## 重要边界

本数组是斗地主记牌器的基础 54 张牌配置；具体对局仍以事件中的 `data_cards`、`CardId`/`card_id` 为准。`CardName`、`Name`、`cardName` 等字段只用于事件对象的名称兜底或技能牌显示，不会改变基础牌 ID 的拆解规则。
