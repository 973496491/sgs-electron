## 已验证的本地读取方法

Chrome 未开启命令行远程调试端口，也没有现成浏览器连接工具，因此未读取当前页面 JS 运行时对象。Windows UI Automation 能枚举现有标签标题，但不等于能读出 Canvas 游戏的数据。

本机磁盘缓存位置为 `%LOCALAPPDATA%/Google/Chrome/User Data/Default/Cache/Cache_Data/`，使用 Chromium blockfile 格式（`data_0`～`data_3`、`f_*`），不是 simple cache 的 `*_0` 文件布局。普通 Python open 读取正在使用的 data 文件会遇到 PermissionError；以只读访问并允许共享读写删除打开成功（Win32 CreateFileW share=7，或 .NET FileStream 的 FileShare.ReadWrite|Delete），不需要关闭浏览器。

实际解析 `data_1` 的 256 字节 entry：8192 字节头后按块读取；key_len 在偏移32，短 key 在偏移96；四个 stream 长度在40，地址在56。stream1 为响应体。地址最高三位类型区分外部 `f_XXXXXX` 与 blockfile，内部地址的 file selector 为 bits16～23，块号为低16位；块大小依类型为36/256/1024/4096，数据起点8192。只筛选十周年静态资源 URL，读取副本写入调查目录。短 key 之外的长键、缓存淘汰及读取期间变化未实现通用处理；不能把本次方法描述为完整浏览器缓存导出器。

### 已跑通的十周年解密方法

原生`CtrUtil`在官方引擎包的`laya.core.min.js`末尾，并非启动脚本或`ConfigWorker.min.js`内。`CtrUtil.native.js`保留完整原生类，`decode-config.cjs`只离线调用所需部分：

1. 创建`WebAssembly.Memory({initial:256,maximum:256})`（16MiB），实例化本地`resc`，导入`{env:{memory,STACKTOP:0}}`。
2. 按原生初始化顺序调用导出`e([0],[0],256)`、`f([0],[0],256)`、`d([0],[0],128)`；数据指针16384。这里保留原生JS参数转换，不把`[0]`解释成已提取的明文密钥。
3. 对单个密文补`16 - (length % 16)`个零字节（整块也补16），写入数据区，调用`a(pointer,paddedLength)`；随后`d([0],[0],128)`复位，结果截回密文原长。
4. 配置成员得到gzip（头`1f8b08`），`node:zlib.gunzipSync`后解析JSON。缓存主程序按同一封装解密后得到ZIP，内部`main.min.js`为29235625字节；主程序这一步**不做gzip/JSON解析**。

执行`node tmp/ten-year-userscript-audit-20261120/decode-config.cjs --main`可复核。4份配置均通过gzip完整性检查、JSON解析、与实际原生`CtrUtil.Ofb_Dec`封装输出逐字节相等及重复解密复位一致；对照调用仅用最小字节存储对象替代`Laya.Byte`的三项存储操作，不运行整套游戏引擎。验证结果及明文哈希在`decode-result.json`。本次不推断底层算法名、不复用OL普通AES Key/IV，也不把此成功视为OL `_w`分支已经完成。
